# User guide

## Projects and storage

Create a named project and choose its discipline. The selected template defines the extraction fields, repeating observations, prompt and CSV columns. Select the intended provider/model in the project header before running a batch. A model marked as missing a key needs the corresponding `.env.local` entry and a server restart.

Project metadata and optional Elsevier credentials use localStorage. Project state and PDF blobs use IndexedDB (`BioReviewProDB_v3`). Storage belongs to the browser profile and origin, including the port. A different browser, port or device will not automatically see the same data. Clearing site storage or deleting a project can remove locally stored work. Export results regularly and retain source PDFs separately.

## Title and abstract screening

Import MEDLINE/PubMed text (`.nbib` or `.txt`) or RIS (`.ris`). PubMed XML and arbitrary spreadsheet layouts are not supported by these parsers. A missing abstract is not evidence that a study is ineligible.

Enter inclusion/exclusion criteria in the sidebar. Human decisions and AI suggestions occupy separate fields. `INCLUDED` and `NOT_SURE` human decisions pass to the full-text stage. `EXCLUDED` and `UNREVIEWED` human records do not. The Conflicts view includes human uncertainty and certain human–AI disagreements; it is a review aid, not a substitute for checking every exclusion.

AI screening can run on individual records or sequentially in a batch. Stop a batch using its stop control. Bulk screening skips records with an existing AI verdict; changing the model does not automatically create a separate run or preserve the previous response. Use separate projects and exports when comparing models or runs. Persistent errors may need stopping and correction before restarting a batch.

## Full-text screening

Enter the full-text eligibility criteria separately. The copy-from-title/abstract control can be used as a starting point, but does not establish that the criteria are appropriate for full-text decisions.

Attach a PDF to an individual record or use folder linking. Linking uses filenames, identifiers and title similarity, so check the matched document before screening. Replacing a full-text PDF invalidates its previous AI full-text suggestion. The app can attempt automatic retrieval, but manual attachment is the most self-contained route; the optional Elsevier proxy is not included (see [Configuration](CONFIGURATION.md)).

Read the full text and record the human eligibility decision and exclusion reason where appropriate. AI full-text suggestions can be `INCLUDED`, `EXCLUDED` or `NOT_SURE` and include reasoning and a suggested exclusion reason. AI decisions do not replace the human status. Only human full-text inclusion advances records through the normal screened workflow to extraction.

## Extraction and verification

Advance eligible records or upload PDFs directly on the extraction screen. Direct uploads can bypass the screening stages. Check the template and optional Focus terms before triggering extraction; changing focus changes the effective task.

Study fields appear in the result card and repeating observations in tables. Zebrafish and rat templates use endpoint rows; the microplastics template uses soil/field measurement rows. Missing fields, non-significant findings, multiple concentrations, sexes, tissues, generations and assessment times require source checking. A schema-valid response is not evidence of complete or correct extraction.

The PDF viewer displays the source beside the extracted fields. Evidence controls pass a text-search fragment to the browser PDF viewer; search behaviour varies by browser and PDF text layer. Evidence snippets are model outputs and must themselves be verified. Scanned, encrypted or otherwise unreadable PDFs may need preparation outside this application; there is no separate local OCR pipeline here.

Re-extract uses the current model, template and focus, replacing the stored extraction on success. Enrichment sends the prior partial extraction with the PDF and asks for a complete revised object; it is not independent validation. Export the prior version before either operation if you need an audit trail.

## Export and re-import

Export results from each stage. Screening/full-text CSVs include human decisions and AI fields. Extraction columns are generated by the selected template, including record ID, filename, study fields, repeating fields and Evidence JSON. A study can contribute several rows; a row count is not automatically a count of correctly extracted observations.

Use Import results for CSVs exported by this app and select the same discipline for extraction files. Screening records are merged by identifier; extraction records are merged by numeric record ID. Existing values can therefore be overwritten. Import into a new project when uncertain. CSVs do not contain PDF bytes or all project settings. Relink local PDFs after importing results. Screening CSV parsing is line based, so embedded line breaks in quoted fields can prevent reliable round trips; inspect imports before using them.

## Troubleshooting

| Symptom | Action |
| --- | --- |
| Model shows no key | Fill the correct entry in `.env.local` and restart Vite. |
| Unknown model, access denied or quota error | Check the exact model string and account access with the provider. An adapter does not guarantee access. |
| Gemini reports `MAX_TOKENS` | Export existing work; inspect the task and response size. Narrow focus or deliberately change the cap in `providers/util.ts`, recording the change. |
| Invalid JSON or missing output | Inspect the original task/document and provider error. Other adapters do not have equivalent explicit truncation checks. |
| PDF cannot be fetched | Attach it manually. Remote servers, CORS restrictions or the absent Elsevier proxy can prevent retrieval. |
| Wrong PDF linked | Replace it manually and rerun the relevant suggestion/extraction. |
| Project appears missing | Return to the same browser profile and origin/port. Do not clear its site storage. |
| CSV import looks wrong | Use a fresh project and an unmodified app export; check headers, IDs and embedded line breaks. |

Use the synthetic example before importing research materials. Model output remains a suggestion for human review.
